# Embed only summaries

### In some RAG workflows, embedding entire documents can be inefficient, especially when the source text is lengthy, repetitive, or contains irrelevant sections. Instead, a more resource-efficient approach is to generate concise summaries of each document and embed only those summaries into the vector store.

### This strategy reduces the storage footprint and speeds up retrieval, since the embedding represents only the most important information. Summaries can be generated using LLM-based summarization tools, extractive algorithms, or domain-specific heuristics. Once embedded, they still preserve the essential meaning of the original document, allowing the retrieval step to remain semantically accurate while avoiding noise from unimportant text.

### For example, instead of embedding an entire 50-page technical report, we might store a 500-word abstract that captures the core findings. At query time, the system retrieves the relevant summaries, which can then be expanded by referencing the original full text if needed.

### Embedding only summaries is particularly useful when working with large corpora, resource-constrained environments, or datasets with high redundancy, making RAG pipelines faster, lighter, and more cost-effective without sacrificing relevance.

### This recipe demonstrates how to write a program to embed only summaries:
1. Define several long-form documents that will be summarized. These serve as source texts for generating concise summaries, which will later be embedded into a FAISS vector store for semantic search.

2. Create documents with metadata. These documents will be used to demonstrate metadata filtering in the FAISS vector store.

3. Initialize the summarization pipeline. This uses a pre-trained model to generate summaries of the documents.

4. Generate summaries for the documents. This will create concise summaries for each document.

5. Create a FAISS vector store from the summaries. The FAISS vector store will allow for efficient similarity search on the embedded summaries.

6. Perform a semantic search on the vector store. This query will find documents similar to the input text based on their embeddings.

7. Print the results with summaries.
